## 발견한 원인과 수정

1. **HTML 구조 손실**: 제목·표의 행/열·병합셀·조건이 평문에서 섞였다.
   공식 본문 컨테이너에서 사업 제목과 필드, 표의 소유 관계를 보존하도록 수정했다.
   탐색 메뉴·게시판 목록·표 설명 문구는 답변 사실로 사용하지 않는다.
2. **질문 목적 혼동**: 정의·대상·제공 서비스·주의사항·공시일·이의신청 기간을 구분했다.
   시간+위치, 대상+서류 등 복합 요청은 요청한 필드를 함께 안내한다.
3. **검색의 과도한 거절**: 질문 형식·일반 증상·기관 표현을 독립 업무로 요구하던 조건을
   수정했다. 검사비용·법정감염병·정신건강 등 실제 서비스가 있는 원문을 검색에서
   탈락시키지 않으며, 원문의 업무 일치 및 게시판·다른 사업 차단 검사는 유지한다.
4. **필수 조건 누락**: 지원대상의 연령·소득·거주·취업 조건, 지원비율과 한도,
   예외·예약·금식 조건을 같은 사업의 항목에서 함께 유지한다.
5. **불필요한 재질문**: 일반 주민 대상이라는 이유로 재질문하지 않는다.
   민원 종류·위기사유·접종 종류·보험 유형·동별 위치처럼 필요한 범위만 한 번 확인한다.
   동 선택 후 실제 해당 동의 행을 읽고, 미확보 지역을 첫 번째 시설로 대체하지 않는다.
6. **오래된 자료**: 크롤링 확인일과 본문의 기준연도를 구분한다. 예전 모집·첨부파일
   연도는 주의 표시하며, 검토된 구식 인증방법·미확인 공시일은 안내를 보류한다.
   현재 응시료 지원 및 비상급수시설 페이지를 공식 사이트에서 새로 수집·정제·임베딩했다.
7. **URL 손상**: 공식 URL의 mId·첨부파일 ID를 전화번호로 잘못 마스킹하던 문제를
   수정했다. 사용자 개인정보 검사 및 다른 도메인·임의 매개변수 검사는 유지한다.

명확한 필드는 현재 공식 원문에서 바로 읽으며 **일반·복잡한 질문은 Gemma의 근거 선택
경로를 유지**한다. 모델이 고른 항목도 업무·조건·완결성을 검증한다.
핵심 답변은 480자 이내이고 긴 원문은 접힌 영역에 제공한다.

## 로컬 실행 기록

- `data/faq100_audit_20261011/`: 수정 전 원본 결과·원문·수동 검수.
- `data/faq100_improved_20261011/`, `data/faq100_final_20261011/`,
  `data/faq100_verified_20261011/`: 중간 수정·회귀 문제 재현 기록. 최종 결과로 집계하지 않음.
- `data/faq100_release_20261011/api_results.json`: 개선 전체 100문항 실제 API 응답.
- `final_rechecks.json`, `supplemental_rechecks.json`: 마지막 보완 및 후속 흐름 실제 응답.
- `official_sources.json`, `manual_review.json`, `summary.json`: 근거 스냅샷·문항별 판정·집계.
- 원문 전체 HTML 스냅샷: `data/faq100_audit_20261011/html_sources.json`.
- `data/faq100_fix_tests.log`: 마지막 309개 검사 결과.

원본 Excel은 수정하지 않았다. 실행 기록과 로그는 Git에서 제외되는 로컬 `data/`에 보관한다.
API 키·비밀번호는 평가 문서·코드·로그에 기록하지 않는다.
