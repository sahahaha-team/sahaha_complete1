# 일반 질문의 답변 거절 원인 조사

## 조사 조건

- 조사일: 2026-10-08.
- 실행 환경: 현재 로컬 FastAPI, 실제 Supabase, Ollama `gemma2:2b`,
  `SOURCE_ONLY_ANSWERS=true`.
- 실제 API에 독립 세션으로 질문 6개를 요청하고 검색·최신성·근거 검사·원문 선택을 추적했다.
- 제공받은 100개 질문의 지정 공식 URL과 DB 원문을 대조했다. 엑셀의 초안 답변은
  행정 답변의 근거로 사용하지 않았다.
- 아래 조사 결과는 수정 전 상태다. 이후의 상담 코드 보정은 이 문서의 마지막 절에 기록한다.

## 확인 결과

### 1. 자료가 있어도 표면적인 단어 일치 조건에서 제외된다

`chatbot/retriever.py::_content_keywords`가 질문의 명사를 뽑고,
`chatbot/evidence.py::topic_support`는 그 단어가 문서에 실제로 나타나는지 검사한다.
키워드가 2개 이하면 전부, 그 이상이면 75% 이상을 요구한다. 키워드 3개도 모두
일치해야 한다. 주제와 신청 항목, 질문 표현을 충분히 구별하지 못하고 동의어 보정도 제한적이다.

실제 재현:

- 질문: `냉장고 무료 수거 신청 방법 알려줘`.
- 추출된 단어: `냉장고`, `무료`, `수거`.
- 공식 폐가전 안내 페이지가 검색 결과 첫 번째에 있었고, 최근 확인 기준도 통과했다.
- 원문은 `무상수거`라고 표현한다. `무료`와 연결하지 못해 근거 검사를 통과한 결과가
  15건 중 0건이 되었다.
- API는 `degraded_reason=low_confidence`로 대표전화 안내를 반환했다. 모델 호출 전 단계의 실패다.

100개 질문의 지정 공식 원문 검사에서는 98개 질문에 대응하는 페이지가 DB에 있었다.
80개는 단어 검사를 통과했고 20개는 탈락했다. 탈락 중 **18개는 대응 페이지가 존재**했다.
예를 들어 `날짜`, `도움`, `때문`, `이용`, `보건소` 같은 표현이 원문 본문에 없다는 이유가
탈락에 영향을 주었다. 구청 위치 질문에서는 `사하구청`이 지역어로 지워져 주제어가 없었다.

이는 지정 원문에 대한 단어 검사 결과다. 검색 성공률이나 실제 답변 정답률로 해석할 수 없다.
나머지 2개 질문의 지정 URL은 조사 당시 DB 원문에 없었다.

### 2. 주제 일부가 겹친 문서를 먼저 선택한 뒤 다음 자료를 충분히 시도하지 않는다

`전입신고`는 주제어 `전입`만 남는다. 실제로 `전입신고 어떻게 해?`에 동 홈페이지가
선택되었고, 주민등록등본 발급 문의에는 무인민원발급안내가 먼저 선택되었다.
일반 발급 안내와 다른 사업의 구비서류에 적힌 `등본`도 구별하기 어렵다.

`chatbot/source_answers.py::build_source_answer`는 앞쪽 5개 검색 청크에서 최초로
원문 발췌가 가능한 문서를 선택한다. 같은 URL의 청크가 중복될 수 있으며,
최종 짧은 답변으로 질문의 요청 항목을 설명할 수 있는지는 그 다음 단계에서 검사한다.
이때 설명을 못 하면 다른 문서를 다시 시도하지 않고 재질문으로 끝날 수 있다.

실제 API에서 전입신고 방법과 주민등록등본 발급 방법 질문은 모두 이미 요청한
`신청 방법`을 다시 선택하라고 물었다. `scope_question`이 원문의 항목만 보고
선택지를 만들고, 사용자가 이미 물은 항목을 제외하지 않는 것도 반복 원인이다.

### 3. 서로 다른 실패 원인이 동일한 거절 문구로 표시된다

현재 기본 설정은 공식 원문에서 확인한 문장·표·연락처만 안내하는 방식이다.
일반 상담도 `SOURCE_ONLY_ANSWERS=true`이면 자유로운 LLM 답변 생성 단계까지 가지 않는다.
이를 설정했다는 사실 자체보다, 위의 엄격한 근거 검사와 제한적인 원문 선택이
결합되어 관련 자료를 답변에 활용하지 못하는 것이 이번 재현의 원인이다.

`chatbot/conversation.py`는 단어 검사 실패(`low_confidence`)와 적합한 원문 추출 실패
(`no_current_evidence`)에 같은 대표전화 안내를 사용한다. 화면만 보면 자료 부재,
검사 탈락, 추출 실패를 구분하기 어렵다.

## 장애와 구분한 사항

- DB 조회는 정상이다. 웹 원문 174건, 검색 문서 586건을 확인했다.
- 웹 원문 174건 모두 확인일이 2026-10-07이며, 조사 시점의 7일·30일 최신성 기준을 통과했다.
  이는 최근 웹 확인 여부이며 모든 원문의 행정 내용이 최신임을 보장하는 수치가 아니다.
- 조사 환경에 서비스 키가 설정되어 있었다. 키의 값은 기록하지 않았다.
- 정화조 청소 주기, 재산세 납세자, 보건소 운영시간 질문은 공식 출처가 있는 답변을 반환했다.
- 재현한 냉장고 질문은 Ollama 호출 전에 거절되므로 모델 다운로드나 모델 교체로 해결되지 않는다.

## 필요한 공통 개선

1. 핵심 서비스·시설명과 질문 항목·일상적인 요청 표현을 분리하고, 명확한 동의어를 연결한다.
2. 문서의 중심 업무와 질문의 의도가 맞는지 검사한다. 구비서류의 우연한 단어 일치를 답변 근거로 쓰지 않는다.
3. 서로 다른 공식 URL을 비교하고, 요청한 항목을 실제로 설명할 수 있는 원문을 선택한다.
4. 이미 명확한 질문에는 같은 항목을 다시 묻지 않는다. 여러 사업·대상 조건이 겹칠 때만 필요한 조건 한 가지를 묻는다.
5. 확인된 숫자·예외·출처·최신성 검사는 유지하고, 실패 단계를 구분해 기록한다.

개별 질문의 예외를 계속 추가하거나 전체 근거 검사를 완화하는 방식으로는 이 문제를
해결하기 어렵다. 일반 검색과 근거 선택 경로를 함께 보정한 뒤 실제 답변을 별도로 평가해야 한다.

## 조사 결과에 따른 상담 코드 보정 — 2026-10-08

- `CrawledPageIndex`로 전체 크롤러 원문을 검색한다. 5분 캐시·페이지 단위 조회를 사용하며,
  임베딩 청크가 없는 페이지도 공식 본문과 최근 확인일이 있으면 활용한다.
- 서비스명과 요청 항목을 분리하고 명확한 동의어를 연결한다. 서비스명은 다른 조건어의
  일치로 대체할 수 없으며, 증명서 발급 요청에 다른 사업의 구비서류 문서를 제외한다.
- 서로 다른 공식 URL을 비교하고, 요청한 항목을 실제로 설명할 수 있는 짧은 답변을
  만들 수 있는지까지 검사한 후 원문을 선택한다.
- 방법·대상·비용·주기·서비스 내용·위치·운영시간을 구분한다. 제공 서비스 목록, 줄바꿈
  항목, 완결된 명사형 안내도 원문의 구조를 유지해 읽는다. 숫자 표의 임의 대응은 금지한다.
- 신청 방법에 실제 채널 이름을 표시하고, 관련 제외 조건·예외·접힌 원문·출처를 유지한다.
  이미 요청한 항목을 다시 선택하라고 묻는 흐름을 제거했다.
- 검색 결과 수·최근 확인 통과 수·서로 다른 근거 URL 수를 로그에 기록한다.
- 공식 질문 자료의 페이지 갱신 결과: 100개 URL 중 98개 확인·갱신, 2개 유효 본문 미확인,

  요청으로 오인하지 않는다. 여권의 명확한 요청 항목도 포괄 메뉴로 되묻지 않는다.
