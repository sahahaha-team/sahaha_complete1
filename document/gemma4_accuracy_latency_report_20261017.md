## 1. 요청별 계측과 모델 호환 계약 확인

- 요청 식별자를 상담 HTTP 응답과 검색/최신성 검증/의미 재정렬/원문 준비/모델 호출
  시간에 연결했다. 모델 적재·입력·생성·토큰 수·종료 상태를 보존한다. 알 수 없는 값은
  0 대신 null이다. 오류 요청에도 경과 시간과 예외 종류만 기록한다.
- 관련 회귀30개 통과(12.348초). 실제 API4턴은 수정 전 실행 프로세스의 답변과
  동일했다. HTTP200만으로 정확하다고 판정하지 않고 기존 원문 대조 기준을 사용했다.
- 합성 자료2개/oneOf 스키마의 실제 Gemma4 호출은 올바른 자료0/항목0을 선택했다.
  think=false, stream=false, context4096/출력100 옵션을 확인했다. thinking 출력 없음.
  입력259/출력14토큰, 총9.569초 중 입력 처리8.221초/생성1.172초/적재0.057초.
  합성 계약 검사이며 행정 질문 정답률이 아니다.
- 계측판 AE010은22.721초 중 의미 재정렬15.667초였고 Gemma 호출은0회였다.
  AE015는8.142초 중 모델2.334초, AE020은6.256초 중 모델2.483초였다.
  이 두 모델 선택은 원문 검사에서 거부됐다. 전체 지연을 Gemma4 추론 탓으로
  돌릴 수 없으며, 확인된 충돌/미수집 항목에도 후보 문장이 남아 불필요한 추론이 있었다.
- 기존 서버의8턴 진단에서 AE01525.907초/AE01026.161초였다. 이 진단 중 파일에
  계측을 편집했지만 서버는 이전 코드를 계속 실행했다. 원자료 code_unchanged=false를
  보존한다. 새 서버는 Worker가 갱신한 원문 색인을 다시 읽었으므로 위 두 실행을
  엄밀한 동일 자료 속도 비교로 사용하지 않는다.
- 재시작 초기 원문 전체 색인 준비가90초를 넘었다. 질문 검사는 시작하지 않았고

- 시작 시 광역 수집259건의 원문 일괄 조회에서 DB statement timeout이 관찰됐다.
  공식 우선 페이지109건 갱신과 광역 수집 실패를 구분한다. 기존 색인은 보존돼 있다.

## 2. 검토된 충돌·요청 항목 부재의 불필요한 선택 호출 제거

- 검토 레지스트리와 현재 원문의 표식이 일치하고 요청 항목이 차단된 경우, 충돌
  이유와 실제 공식 출처를 제공한다. 바뀐 원문·다른 업무·혼합 요청에는 일괄 거절을
  적용하지 않는다. 다른 적격 공식 자료가 요청 항목을 제공하면 정상 경로를 사용한다.
- 대상·예외 문장만 있고 질문의 실제 항목이 없는 후보는 선택기로 보내지 않는다.
  JSON 형식이 맞아도 약품 용량 등 없는 사실을 선택할 수 있게 두지 않는다.
- 관련 회귀34개 통과(6.136초). 실제 API4턴은 신규발급 순서S, 층수 충돌I,
  미확인 복용량I, 물리치료 대상S로 대조했다. 네 요청 모두 Gemma 호출0회다.
- AE0203.614초, DClinic0.790초. AE015는 모델을 생략했지만 재정렬6.437초를
  포함해10.893초였다. 전체 지연 개선 완료로 계산하지 않으며 다음 단계에서
  확인된 충돌이 재정렬 전에 처리될 수 있는지 보완한다.

원자료: `evaluation/results/gemma4_latency_stage2_20261017.json`.

## 3. 로컬 요청 시간 제한·복구 대기·가중치 식별

- 설치된 ChatOllama가 만드는 동일 JSON Schema/think=false/출력 제한 요청을
  비동기 HTTP로 전송하고 상담 선택 호출에 기본30초 전체 시간 제한을 적용했다.
  시간 초과 시 클라이언트 연결을 닫고 별도 실행 스레드를 남기지 않는다.
- 웹·태깅 Worker가 같은 프로세스 간 잠금을 사용한다. 이미 사용 중이면
  검증된 원문 경로로 진행하고 태깅은 원문 메타데이터를 보존한다. 배치 실패 때
  같은 요청을 청크별로 즉시 반복하지 않는다. 시작된 배치 작업을 상담이 강제로
  선점하는 구현은 아니므로 실제 작업 중에는 모델 검토가 제한될 수 있다.
- 실제1초 취소 시험에서 클라이언트는1.030초에 종료됐으나 Ollama는 입력 배치를
  마칠 때까지 지연 취소했다. 후속 요청 총18.123초/실제 입력1.221초·생성1.000초였다.
  로그 task85는1325토큰 입력 중512에서 취소·해제됐다. 즉시 중단을 주장하지 않는다.
- 이에 시간 초과 후 공유 복구 대기60초를 추가했다. 재시험은1.056초에 시간 초과,
  바로 다음 요청은0.022초에 ModelBusy로 끝나 새 추론을 제출하지 않았다. 원문으로
  답할 수 없으면 처리 지연/사용 중/연결 장애를 정보 부재와 구분해 안내한다.
- 실제 Gemma4 oneOf 선택은1.772초, 올바른 자료0/항목0, 생각 출력 없음으로 확인했다.
  같은 모델 이름의 가중치 digest가 바뀌거나 확인되지 않으면 선택 캐시를 재사용하지 않는다.
- 전체 회귀566개 통과(14.094초) 후, 추가한 관련 검사31개와12개도 통과했다.
  최종 전체 검사는 후속 보완 완료 후 다시 실행한다.
- 실제 API 최종4턴은S2/I2, 모델 호출0회이며 기존 사실·예외와 충돌 안내를 유지했다.
  AE0012.671초/AE01016.391초/AE01510.377초/AE0203.881초다. AE015의 조기
  검토6.103초와 AE010의 재정렬8.580초가 남아 있어 전체 속도 목표는 미달이다.
  조기 검사는 재정렬을 생략했지만, 관련 없는 후보의 항목 검사 비용이 남아 후속 보완한다.
- 웹과 Worker를 함께 실행했다. Worker의 우선 공식109페이지 재확인과 본문 부족1개
  partial 상태를 유지하며, 광역 수집·원문 색인 초기화 비용과 상담 지연을 구분한다.
