# 축제 일정 오안내 진단·보완 (2026-10-27)

## 진단

- 사용자 재현 질문 `감천문화마을 축제언제해`와 `26년 감천문화마을 축제 언제냐고`를 실제 HTTP API에서 먼저 확인했다. 모두 함평군 자매결연 페이지의 **2024.10.25 축제 방문 실적**을 일정으로 안내했다. 해당 페이지의 다른 행사에는 2026년도 있어, 페이지 전체에서 연도만 찾는 방식도 안전하지 않았다.
- 변경 전 저장 본문에서 감천문화마을을 언급한 페이지 17개를 확인했으나 현행 행사 일정 공고는 확보되지 않았다. 이는 공식 공고가 존재하지 않는다는 뜻이 아니다. 사하구 문화관광 메뉴가 기본 수집 시작점에서 빠져 있었고, 게시판의 `href="#"`/`boardView(...)` 상세 링크도 기존 링크 추출이 놓쳤다. 사하구 자체 행사 일반 안내는 `매년 10월 중` 수준이다.
- 부산광역시 공식 행사 공고에서 **제16회 감천문화마을 골목축제, 2026-10-31~2026-11-01, 10:00~18:00, 감천문화마을 일원**을 확인했다. 구청 게시판의 한정 검색에서는 같은 2026년 상세 공고를 찾지 못했으며, 이를 구청 사이트 전체에 자료가 없다는 증거로 확대하지 않았다.

공식 근거: https://www.busan.go.kr/eng/bsevents/1757816

## 구현

1. 축제·공연 등 행사 일정 질문에서 요청 연도, 올해·내년 등 상대 연도, 명시하지 않은 현재 일정의 연도를 분리한다. `26년`도 2026년으로 해석한다. 확인일·다른 행사의 연도·제목의 연도로 다른 날짜를 정당화하지 않는다. 교류·방문 실적은 일정 안내의 근거로 쓰지 않되 교류실적 자체를 묻는 질문은 구분한다.
2. 연도만 정정하는 답과 시간·장소 후속 질문에 행사명과 연도 조건을 유지한다. 시간에는 실제 시각, 장소에는 실제 장소 필드를 읽는다. 기간 조회에서 일일 운영시간 때문에 행사 기간이 누락되지 않도록 한다. 다른 시설의 완전한 새 질문은 기존 행사에 연결하지 않는다.
3. 사하구 문화관광 수집 시작점과 게시판 상세 링크 복원을 추가했다. 정해진 `boardView` 인수만 읽고 같은 호스트의 게시판 상세 주소를 구성한다. 자바스크립트를 실행하지 않는다. 기존 수집 범위·깊이·페이지 상한은 유지한다.
4. 검토한 부산광역시 **단일 공식 URL**을 등록했다. 도메인 전체나 임의 외부 사이트를 공식 출처로 허용하지 않는다. 원본 HTML과 제목·기간·시간·장소의 실제 필드를 보존하고 정제·색인·공식 페이지 갱신 목록에 연결했다. 날짜나 답변을 FAQ 코드에 상수로 넣지 않았다.

## 자료·실행 검증

- 실제 원본 HTML 60,589자와 정제 청크 1개·벡터 문서 1개 저장을 확인했다. 공식 원문 재조회와 저장 본문의 사실 필드가 일치했다. `evaluation/results/event_schedule_20261027_sources.json`에 검증 시각·HTML 해시·저장 상태를 남겼다.
- 초기 원문 수집은 성공했으나 기존 사하구 전용 정제기로 다시 파싱하면서 유효 청크가 사라지는 실패를 발견했다. 외부 공식 행사 파서 경로를 정제기에도 적용한 뒤 실제 색인 성공을 확인했다. 부산시 재조회 중 연결 종료 1회도 기록했고 재조회 성공을 확인했다. TLS 검증을 해제하지 않았다.
- 최종 전체 회귀 **709개, 20.920초 통과**. 단위 테스트 수이며 주민 질문 정답률이 아니다. 11개의 행사 관련 테스트에 실제 HTML 조각, 요청 연도·교류 기록·정정 문맥·필드 선택·출처 허용 범위·게시판 링크 복원을 포함한다.
- 첫 실제 개발 검사 20턴에서 날짜 오답은 사라졌으나 시간 후속에 장소를 답하거나 장소 후속에 근거 부족을 반환하는 오류가 관찰됐다. 이 기록은 `event_schedule_20261027_intermediate.json`으로 보존한다. 수정 도중 실행한 기록이므로 동일 최종 버전 성능으로 합산하지 않는다.
- 10/27 13:29~13:31 KST 최종 실제 API 20턴: **충분 S14 / 확인 C1 / 근거 부족 I5**. 관찰한 오안내·실행 오류는 없었다. 중앙값 5.265초 / p95 8.448초 / 최대 8.638초. 로컬 Ollama `gemma4:e4b` digest는 이전 고정 평가와 같고, 이 표본의 실제 모델 호출은 0회였다. 확인 질문·근거 부족 안내는 충분 답변에 합산하지 않는다.
- 10/28 10:39~10:41 KST 재개 후 같은 20턴을 새로 실행했다. **S14/C1/I5**, 중앙값 **3.644초 / p95 7.029초 / 최대 8.477초**, 요청별 기록 20개 대조·모델 호출 0회다. 기간·시간·장소 후속 및 연도 정정 9턴은 모두 원문의 해당 필드를 안내했다. 10/27과 10/28 결과를 한 번의 표본으로 합산하지 않는다. 후자는 운영 Worker가 진행되는 개발 재검사이며 고정 데이터 평가가 아니다.
- 10/28 전체 회귀도 **709개, 16.456초 통과**했다. 공식 공고를 이날 10:40 KST 다시 조회해 저장 본문과 일치함을 확인했다. 보건소·도서관·소방 예약 안내 및 직원업무안내 11페이지의 직통번호는 별도 원문 대조 기록을 남겼다. 원시 응답·수동 원문 대조 판정은 `evaluation/results/event_schedule_20261028_reviewed.json`에서 연결한다. 개발 담당 AI의 검수이며 독립·블라인드 평가나 전체 주민 질문 정답률이 아니다.

## 한계와 운영 범위

- 특정 행사 공고 한 건을 확보했다고 모든 행사·향후 연도의 공고까지 수집한 것은 아니다. 미등록 외부 기관 공고는 확인 후 개별 등록이 필요하다. 사하구 게시판 상세 링크 보완도 사이트 전체 크롤링 완료를 의미하지 않는다.
- 2024년 전체 행사 공고와 2027년 공고는 이번 확보 자료에 없다. 해당 질문에는 다른 연도 방문 기록이나 올해 날짜를 대신 답하지 않는다.
- 기존 Worker의 전체 공식 자료 갱신은 별도 상태이며, 이 작업의 단일 공고 적재를 전체 최신성 확보로 표시하지 않는다. 학교 내부망 제외, 로컬 Ollama/Gemma4 유지, UI·음성 기능 추가 없음.
- 웹 서버 시작 시 원본 페이지 전체를 준비하는 시간이 수 분 소요됐다. 이는 준비 이후 개별 응답 시간과 구분한다.
- Worker는 10/27 진행 중 작업이 없을 때 PID23856에서31328로 재시작해 새 수집 코드를 적용했다. 10/28 10:33 KST PC 중단/복귀 구간에서 DNS·DB 연결 오류로 전체 공식 갱신이 실패한 기록이 있다. `last_result=111개/실패1개`는 과거 기록이며 오늘 성공 결과가 아니다. 10:40부터 증분 크롤링은 실제 `running`으로 복구되어 진행 중이다. 완료로 표시하거나 큐를 일괄 초기화하지 않았다. 직원 안내는 자동 갱신된1137행이며 그에 따른 연락처 스냅샷 변경은 이번 행사 수정 커밋에 섞지 않는다.
