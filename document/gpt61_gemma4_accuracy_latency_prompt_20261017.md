- 현재 검색·정규화·의미 검색이 실제로 어느 경로에서 동작하는지 확인한 후 원인을 고쳐줘. BM25나 벡터 검색이 이미 있다면 중복 도입하지 마. 벡터 유사도는 사실 근거나 답변 확률이 아니다.
- 띄어쓰기·통칭·질문 어미·가벼운 오타·짧은 후속 질문을 공통 처리하되 연령, 숫자, 지역, 신규/재발급, 본인/대리, 무료/유료, 부정 표현은 보존해줘. 같은 뜻의 문장과 뜻이 달라지는 최소 차이 문장을 짝지어 검사해줘.
- 모델 후보 검색 실패와 자료 미수집을 분리해줘. 실제 미수집 공식 자료가 원인이면 해당 자료를 확인·추가하고 재수집 대상에 포함해줘. 잘못 수집된 표의 행·열과 대상 관계를 복원해줘. 첨부 문서/OCR은 실제 누락 질문 해결에 필요한 범위부터 진행하고 모든 파일을 다 읽었다고 주장하지 마.
- 연락처는 `data/department_contacts.json`의 공식 업무 조회 경로로 검증해줘. 자료의 갱신일과 수집 성공 시각을 구분하고 만료 기준을 완화해 통과시키지 마.
- 답변은 핵심부터 짧게, 긴 원문은 기존 접힘 영역에 제공해줘. 짧게 만드는 과정에서 조건·예외를 삭제하지 마. 필요한 확인 질문은 한 개만 하고 후속 답을 이전 문의에 연결해줘. 물리치료실 등 충돌 원문을 외부 공식 근거 없이 임의 수정하지 마.
- 개별 평가 문장을 알아보는 정규식과 예외를 계속 추가하는 방식보다 공통 업무 범위·항목·조건 연결 구조를 우선해줘. 큰 리팩터링은 재현된 문제와 회귀 보호 범위가 명확할 때만 해줘.

### 6. 검증·커밋·완료 기준

각 의미 있는 업그레이드마다 관련 회귀 테스트 → 실제 로컬 모델/상담 API 검증 → 원문 대조 → 해당 변경만 커밋 → `hellokack/fix-chat-rendering`으로 GitHub 푸시 순서로 진행해줘. 실패한 업그레이드를 정상 완료로 커밋·보고하지 마. `git add .`를 쓰지 말고 비밀·대형 로컬 모델·사용자 포스터·무관한 파일을 제외해줘. 푸시 후 원격 커밋을 확인해줘.

최종 단계에서 기존555개를 포함하는 전체 회귀와 영향을 받는 실제 API 세트를 실행해줘. 테스트 수가 바뀌면 이유를 기록하고 테스트 삭제로 통과시키지 마. 변경이 없는 동일 대규모 검사를 매 단계 반복할 필요는 없지만 회귀 위험과 완료 기준을 충족해야 해.

평가에는 원래 문제 질문, 자연스러운 표현 변형, 다른 뜻의 유사 질문, 조건 누락, 자료 충돌/만료/없음, 연락처, 후속 대화, 모델 예외/시간 초과를 포함해줘. 독립 검증 질문에는 개발에 쓰지 않은 다른 업무·표현을 포함하고 정답 원문·필수 조건·올바른 URL을 먼저 고정해줘.

충분S/필요확인C/부분P/타당한 근거 부족I/불필요거절R/오안내W/실행오류E를 분리해줘. C/P/I를 충분 답변 정답률에 합산하지 말고 답할 근거가 없는 질문을 무조건 S로 만드는 목표를 세우지 마. 기한 내 답변 성공률과 타임아웃도 별도 기록해줘. 기존 충분 답변의 정당한 이유 없는 퇴행, 새로운 근거 없는 수치·출처·조건 누락이 있으면 원인을 수정한 뒤 채택해줘.

속도는 같은 코드·자료 스냅샷·모델·캐시 조건을 맞춰 비교해줘. 대표 느린 경로는 준비된 상태에서 소수 반복 측정하고 중앙값/p95/최대/실패 수를 제시해줘. cold와 warm, 캐시 hit/miss, 모델 호출 유무, 단독 사용과 제한된 동시 사용을 분리하고 표본이 작으면 p95 해석 한계를 밝혀줘. 빠른 원문 답변의 비중을 늘린 효과와 모델 자체의 추론속도 향상을 구분해줘.

최종 보고서는 원인, 변경 내용, 검증 조건·시각·질문 수·판정 기준, 전후 결과, 커밋/푸시 상태, 남은 문제와 해결되지 않는 이유를 담아줘. `document/project_context.md`와 재개 기록에 다음 작업자가 이어갈 정확한 상태를 남겨줘. 기존 프로그램 실행 상태를 복구하고 학교 내부망 시험은 사용자 결정으로 제외했다고 표시해줘. 관찰 표본의 무오류를 환각0% 또는 전체 질문 정확도100%로 표현하지 마.

## 사용 조건·추론 설정 참고

- 로컬 Gemma4:E4B는 월별 무료 토큰을 소진하는 API 요금제가 아니다. 자체 하드웨어 실행에는 Ollama의 클라우드 사용량 한도가 적용되지 않는다. 하드웨어·전력 비용과 한 요청의 문맥 길이/메모리 제약은 별도다.
- 공식 확인: [Ollama 가격/사용량 FAQ](https://ollama.com/pricing), [Google Gemma4 모델 카드](https://ai.google.dev/gemma/docs/core/model_card_4).
- 개발 모델 기본 추천 `GPT-6.1 Sol / high`는 이 프로젝트의 코드 추적·조건 검증 난도를 고려한 판단이다. `xhigh`는 어려운 원인 분석에서 비교하고 `max`를 기본값으로 삼지 않는다. 상담 Gemma의 thinking 설정과 개발 모델의 추론 정도는 별개다.
- 공식 확인: [GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol), [추론 설정 지침](https://developers.openai.com/api/docs/guides/deployment-checklist). 높은 추론 수준의 실제 이득은 작업 결과로 평가한다.
