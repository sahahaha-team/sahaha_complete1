# 일상 표현과 상담 근거 판정 보완

## 확인 조건

- 날짜: 2026-10-13. 기준 커밋 `c1abc8b`, 브랜치 `hellokack/fix-chat-rendering`.
- 실제 웹 `/api/chat`, 현재 Supabase, MiniLM 임베딩, Ollama `gemma2:2b`, 로컬 Cross-Encoder 사용.
- 시나리오마다 새 세션을 만들고 연속 질문만 같은 세션으로 실행했다.
- 질문 수와 회귀 검사 수는 구분한다. 개발 중 반복한 사례이므로 전체 상담 정답률로 환산하지 않는다.
- API의 `official` 표시는 행정 사실이 모두 맞다는 독립적인 채점 결과가 아니다.

## 답변·재질문·보류 기준

1. 공식 사이트 원문 또는 담당자가 제공한 행정자료인지 확인한다. FAQ의 제안 답안과 내부 수행계획서는 주민 안내의 근거가 아니다.
2. 질문의 업무·기관·지역이 같은지 확인한다. 원문 제목·프로그램 제목·해당 행의 소유 관계를 검사한다.
3. 최근 확인 시각과 원문의 기준 연도·일정을 구분한다. 현재 설정은 일반 자료 확인 30일, 시간·비용·조건 등 변동 정보 확인 7일이다. 오늘 수집한 과거 행사나 `예정` 안내가 오늘의 확정 정보가 되지는 않는다.
4. 대상·방법·시간·비용·서류 등 실제 요청 항목이 현재 원문에 있는지 검사한다. 대상이나 유형이 불명확하면 한 가지를 먼저 확인한다. 일부만 있으면 확인된 항목과 빠진 항목을 구분한다.
5. Gemma는 검증한 원문의 항목을 선택한다. 표시하는 사실은 원문에서 가져오며 미완성 문장·분리된 조건·다른 사업의 항목을 차단한다.

벡터 후보의 최소 코사인 유사도는 0.35, 의미 재정렬의 지원 기준은 raw logit -2.0 및 차점 후보와의 차이 1.5다. 원문에서 업무가 확인된 단일 후보에는 별도 규칙이 있다. 이 값은 후보 선택 신호이며 정답 확률이나 답변의 유일한 허용 기준이 아니다.

이 기준은 이 프로젝트의 공식 정보 상담 규칙이다. 일상적인 표현이 다르다는 이유로 같은 업무의 근거를 거절해야 한다는 규칙은 없다. 일반 상담에서도 업무·시점·요청 항목을 확인하며, 긴급 신고·연락처·검증된 표의 빠른 조회에는 각각 확인한 공식 근거를 사용한다.

## 새로 수집한 공식 자료

- [주민등록증 발급신청](https://www.saha.go.kr/portal/civil/view.do?civilId=1626&mId=0103080100)
- [주민등록증 재발급신청](https://www.saha.go.kr/portal/civil/view.do?civilId=1625&mId=0103080100)
- [주민등록 전입신고](https://www.saha.go.kr/portal/civil/view.do?civilId=1785&mId=0103080100)

현재 원문을 확인해 주민등록증 신규·재발급은 각각 파생 청크·벡터 4개, 전입신고는 5개, 합계 13개를 저장했다. 추가 수집 목록 `resources/additional_official_pages.json`에는 제목과 URL만 저장한다. 기존 공식 자료 수집 명령 및 Worker 갱신에도 포함된다.

민원편람의 상세 화면은 `detailForm`과 세로 표로 구성돼 있었다. 검색창처럼 전부 제거하던 파서를 보완하고, 다른 민원명이 들어간 공통 표 캡션 대신 실제 사무 제목과 항목·값을 보존한다. 원문에 표시된 `처리기간: 즉시`를 실제 카드 제작·수령 기간으로 바꾸지 않는다. 발급 절차 문의에는 흐름도의 `제작(2주 정도 소요)`를 읽는다.

## 평가 및 남은 범위

`data/paraphrase_*.json`의 상세 실행 기록과 `.local/paraphrase_tests.log`는 로컬 진단 자료이며 Git에는 올리지 않는다.

- 수정 전 실제 웹 6턴에서 주민등록증 두 표현은 보류, 자전거 기본 표현은 안내하되 문장 끝을 붙인 표현은 보류, 소방교육 두 표현은 다른 보건소 업무로 오답이었다.
- 개발 중 실제 웹 21턴에서는 주민등록증·전입신고 절차, 자전거의 일상 표현·지도 후속, 소방 체험 대상·예약 원문, 화재 신고와 없는 사업 보류를 확인했다. 모든 요청은 HTTP 200, 실행 중 코드 해시는 동일했다.
- 그 21턴에서 통행 규칙 문의에 보험 자료를 출처로 붙이는 문제가 추가 확인됐다. 마지막 자전거도로 업무명 구분 전 결과이므로 최종 정확도나 전 질문 성공으로 표시하지 않는다.
- 마지막 수정 후 단위·회귀 418개가 통과했다. 통행 규칙의 보험 출처 차단과 기존 지도 조회·업무 전환도 검사한다. 단위 검사 결과는 주민 상담 정답률이 아니다.
- 웹 호출의 분당 10회 제한을 유지했다. 21턴 진단의 일부 응답시간에는 제한 대기가 포함되므로 모델 처리 시간으로 해석하지 않는다.
- 최종 실제 웹 10턴: 2026-10-13 20:30~20:32, 같은 런타임·DB·모델에서 실행했다. 요청 10개 모두 HTTP 200, 실행 중 코드 해시는 동일했고 최장 핵심 답변은 242자였다. 원문과 요청 항목을 검수한 분류는 핵심 안내 6턴·대상/상황 확인 2턴·통행 규칙 근거 부족 1턴·없는 사업의 근거 부족 1턴이다. 전체 서비스 정답률이 아니다.

최종 웹에 수정 코드를 적용했다. Worker의 공식 페이지 갱신에는 추가 URL 목록이 포함된다. 모델·환경변수·DB 스키마와 실행 명령의 변경은 없다. 개발 맥락과 README에도 현재 사용 방법을 반영했다.

- 자전거 현황도의 PDF 파일명에는 2017이 포함된다. 최신 전용도로 지정이나 통행 규칙을 이 링크만으로 확정하지 않는다.
- 현재 확인한 공동주택 소방·방범교육은 특정 관리 책임자 대상이며 장소·일정이 예정이다. 일반 주민의 신청 방법으로 전용하지 않는다. 관련 원문에 없는 일반 주민 교육의 현 일정·접수 방법은 추가 공식 자료가 필요하다.
- 새로운 줄임말과 업무의 원문 누락이 모두 해결된 것은 아니다. 출처 없는 날짜·번호·조건은 만들어 채우지 않는다.
