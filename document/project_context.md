## 2. 프로젝트 목적

**프로젝트명: 사하구청 AI 상담사 프로토타입 고도화**

1학기에 구축한 공식 홈페이지 수집·정제, RAG 검색, 멀티턴 대화, 출처 제공,
개인정보 차단, 반응형 웹을 바탕으로 실제 행정 상담에 가까운 수준으로 고도화한다.
주민이 복잡한 홈페이지 메뉴를 찾아다니는 시간을 줄이고, 자연어 질문으로 필요한
공식 정보와 담당 부서·연락처·첨부서류를 확인하게 하는 것이 목적이다.

1. **환각 억제:** 검색 근거가 부족할 때 잘못된 행정정보를 생성하지 않도록 한다.
2. **사하구 특화 UI:** 고우니와 행정정보에 맞는 화면으로 서비스 정체성을 강화한다.
3. **객관적인 성능 검증:** 실제 행정 질문과 재현 가능한 평가 기준으로 정확도를 입증한다.

## 3. 개발에서 우선할 기준

### 정확한 근거와 최신 정보

- 공식 자료에 없는 날짜·금액·자격 조건·절차·부서·전화번호를 생성하지 않는다.
- 검색 결과가 질문의 실제 핵심 업무와 일치하는지 확인한 뒤 답한다.
- 근거가 부족하면 답변을 보류하거나 문의 내용을 구체화하는 질문을 한다.
- 공지사항 목록의 담당부서 열, 페이지 이동 메뉴, 저작권 안내를 행정 답변으로 사용하지 않는다.
- 대표전화와 업무 담당자의 직통번호를 구분하고 공식 데이터와 교차 확인한다.
- 보고서의 통계는 자료 기준 기간을 함께 표시한다. 과거 통계를 현재 행정서비스의
  금액·대상·운영 조건에 적용하지 않는다.
- 원문 출처와 실제 답변 내용이 일치하도록 한다.
- 신뢰도는 임의의 확률 대신 ‘공식 자료 확인됨’, ‘담당 부서 확인됨’,
  ‘정확한 자료를 찾지 못함’, ‘추가 문의 필요’ 등의 근거 상태로 표현한다.

### 검색과 연락처 안내

계획서의 검색 구조는 **메타데이터 필터 + 벡터 의미 검색 + BM25 + 직원업무안내**다.
분야별 문서 탐색, 가중치 통합과 재정렬, 필요할 때 검색 범위 확대를 수행하며
Recall@5와 MRR 등으로 설정을 비교한다.

현재 추가된 사용자 요구는 **담당 부서와 전화번호 질문을 전용 파일에서 빠르게
답변하는 것**이다. 이 질문에는 로컬 공식 업무·연락처 자료를 먼저 조회한다.
구체적인 업무·지역을 확인하고, 담당자가 겹치면 추가 질문을 한다.
단어가 비슷하다는 이유로 관련 없는 담당 부서를 연결하지 않는다.

첨부 PDF·HWP·HWPX 본문까지 검색 범위를 보강하는 것은 계획서의 개발 항목이다.
파일 형식별 실제 처리 가능 범위와 출처·기준 기간 보존을 확인하며 확장한다.

### 고우니와 행정 상담 UI

계획서가 제시한 상태 표현은 다음과 같다.

| 상태 | 표현 | 적용 상황 |
|---|---|---|
| 기본 | 인사하는 고우니 | 환영 화면과 일반 답변 |
| 검색 | 고민하는 고우니 | 공식 정보를 검색 중 |
| 주의 | 안내하는 고우니 | 개인정보 감지 또는 근거 부족 |
| 완료 | 밝게 안내하는 고우니 | 공식 자료·담당 부서 확인 완료 |

상담 결과에서 핵심 답변, 담당 부서, 공식 전화번호, 원문 링크, 첨부 신청서·안내문,
후속 질문, 정보 확인 상태를 쉽게 확인하도록 한다.
생활 분야별 빠른 질문, 모바일 사용성, 라이트·다크 모드, 키보드 탐색,
대체 텍스트 및 색상에만 의존하지 않는 상태 안내도 계획에 포함된다.

고우니의 반응과 정보 확인 상태가 상담 진행 과정에 맞게 연결되는 경험을 지향한다.

### 문맥과 개인정보

- 최근 문맥을 유지하되 새 주제에 이전 질문의 내용이 잘못 섞이지 않도록 한다.
- 모호한 질문은 대상·연령·분야·지역 등 필요한 범위를 확인한다.
- 역질문에서는 관련성이 낮은 출처를 보여주지 않는다.
- 새 대화 시작 시 문맥을 초기화한다.
- 개인정보가 포함된 입력을 차단하고 대화 이력에 저장하지 않는다.
- 화재 신고에서는 입력한 주소·연락처를 재사용하거나 저장하지 않고 공식 안전 안내만 제공한다.
- 답변에 개인정보가 섞이면 마스킹한다.

### 데이터 갱신과 운영

계획서에는 매일 증분 크롤링, ETag·Last-Modified 확인, 새 페이지와 변경 페이지 처리,
삭제 페이지·벡터 데이터 동기화, 검색 인덱스 갱신이 포함되어 있다.
스캔 PDF의 OCR은 적용 가능성을 검토하는 항목이다.

관리자 인증, 요청 횟수 제한, Supabase 접근 권한, 오류 정보 보호와
검색·생성 단계 장애 시 안전 안내를 유지한다.
대화 이력은 저장 정책에 맞게 관리하고, 영구 저장을 활성화한 경우 삭제 주기를 확인한다.

## 4. 평가 목표 — 계획서 기준

### 데이터셋

최소 **100개 이상**의 실제 행정 질의를 구성하고 튜닝용과 최종 검증용을 분리한다.
행정정보, 복지, 민원, 부서, 연락처, 모호한 질문, 도메인 외 질문,
개인정보 포함 질문, 첨부문서 질문을 포함한다.

### 지표

| 구분 | 확인할 지표·항목 |
|---|---|
| 검색 | Recall@1·3·5, MRR, 출처 적합률, 담당 부서 정확도, 첨부문서 검색 성공률 |
| 답변 | 정답 핵심어, 공식 원문과 의미·조건의 일치, 실제 사용한 출처의 적합성 |
| 환각 | 존재하지 않는 날짜·금액·절차·연락처, 근거 부족 질문에 대한 안전 안내 |
| 개인정보 | 입력 차단, 이력 저장 차단, 출력 마스킹 |
| 안정성 | 관리자 인증, 요청 제한, XSS 방어, DB 권한, 검색·모델 장애 대응 |

- **환각률** = 공식 자료로 확인할 수 없는 내용을 생성한 답변 수 ÷ 전체 평가 답변 수 × 100
- **환각 방어율** = 답변 불가능 질문에 안전하게 거절한 수 ÷ 답변 불가능 질문 수 × 100

학생 및 일반 사용자 **10명 이상**에게 이해도, 정보 탐색 편의, 출처·담당 부서 확인,
고우니 상태의 직관성, 모바일 사용성, 기존 홈페이지 대비 탐색 속도,
사하구 서비스 정체성을 평가받는다. 5점 척도와 자유 의견을 함께 수집한다.

이 수치들은 수행 목표다. 단위 테스트 통과나 소수 시연 질문의 성공을 전체 정답률이나
환각률로 바꾸어 발표하지 않는다. 평가 결과에는 데이터셋·채점 기준·실행 조건·시점을 기록한다.

### 2026-10-07 화재 신고 오답 수정

`당리동 인근 공장 화제 신고는 어떻게해?`에 불법주정차 단속 안내가 출력되는
현상을 재현했다. 지역명·신고 표현 또는 검색 점수만으로 관련 없는 자료를
근거로 인정하던 검사를 수정했다. 화재 신고는 공식 대피·119 안내를 우선하며,
행정 문서는 핵심 업무·원문·최종 발췌 구간을 확인한다. 여권 준비물 요청과
불법주정차 신고 구간도 함께 보정했다. 사하구청 화재 행동요령 페이지를 실제
DB에 추가했다. 이 수정의 검증 결과는 재현 사례 및 표본 질문에 대한 결과이며,
전체 상담의 정답률을 보장하는 수치로 사용하지 않는다.

- 실행: 2026-10-07 22:46, 로컬 FastAPI·실제 Supabase 자료·`SOURCE_ONLY_ANSWERS=true`.
- 결과: 단위·회귀 테스트 78개 통과, 실제 웹 API 질문 9건의 핵심 답변·출처 및
  부적절한 문구 차단 확인. 화재 질문 2개, 여권 신규 서류, 주차 신고, AI 담당 부서,
  보건증 수수료, 건축과 대표전화, 근거 없는 화재 건수, 존재하지 않는 허가 절차를 점검했다.
- 사용자의 화재 질문 응답 시간은 이 실행에서 약 17ms였다. 전반적인 서비스 지연의
  평균이나 상한을 나타내는 값은 아니다.
- 근거 없는 화재 건수·허가 절차는 숫자·조건·출처를 추측하지 않고 답변을 보류했다.
- 재현 기록: 로컬 `data/answer_issue_before.json`, `data/answer_issue_after.json`.

### 2026-10-07 짧은 답변·재질문 개선

사용자는 긴 원문을 그대로 출력하지 말고 핵심을 간추려 답하며, 안내 범위가 넓으면
챗봇이 세부 조건을 되묻도록 요청했다. 검증된 절차와 완전한 원문 문장에서 짧은
안내를 만들고, 긴 발췌는 접힌 **공식 원문 자세히 보기**에 제공한다. 중요한 조건·
유료 예외·기존 여권 지참 조건은 핵심 답변에도 남긴다. 원문의 표 셀을 문장으로
임의 조합하지 않고 비용은 검증된 행에서 읽는다.

여권·복지·대형폐기물·무인민원발급 등 넓은 질문에서 한 가지 조건을 먼저 확인한다.
짧은 답을 재질문에 연결하는 문맥은 세션별 서버 메모리에 최대 30분 유지한다.
새 주제와 대화 초기화 시 이를 정리하며, 답변 완료 후 후속 질문에도 확인한 주제를
이어 사용한다. 사용자 입력과 원문 모두 기존 개인정보 검사·마스킹을 적용한다.

- 검증: 2026-10-07 23:26, 현재 Supabase 공식 자료와 로컬 FastAPI에서 9개 상담 턴 통과.
  여권 준비물 → 성인 → 처음 발급, 폐기물 비용 → 일반침대 1인용, 화재 신고,
  주차 신고, 폐기물 배출 방법, 성인 10년 26면 여권 비용을 확인했다.
- 표본 결과: 확인 질문 33~39자, 핵심 답변 44~165자. 중요 조건과 실제 출처를 확인했다.
- 브라우저에서 성인 신규 여권 답변의 짧은 표시, 접힌 원문 기본 상태 및 펼치기/접기를 확인했다.
- 단위·회귀 테스트 94개와 JavaScript 구문 검사 통과. 이 수치가 전체 답변 정확도를 의미하지 않는다.
- 기록: 로컬 `data/concise_api_results.json`, `data/concise_chat_preview_20261007.png`.

### 2026-10-08 답변이 문장 중간에 끊기는 문제 개선

`요일별 분리수거 뭐해야하는데`를 실제 API에서 재현하니
`재활용품은 반드시 품목별로 분리하여 요일별로`만 출력되었다.
줄바꿈된 문장의 첫 줄을 독립된 안내로 선택하던 것이 원인이었다.
이어지는 원문 문장을 연결하고, 불완전한 조건·괄호·생략 경계의 발췌는 선택하지 않는다.
인접 예외는 기본 규칙과 함께 남긴다. 완결된 안내가 길면 임의로 자르거나 끝을
지어내지 않고 한 가지 조건을 되묻는다. 핵심 답변 상한 480자와 접힌 원문을 유지한다.

해당 질문에는 공식 생활쓰레기 배출표를 직접 읽는 경로도 추가했다. 2026-10-08에
공식 홈페이지 HTML에서 월~일 7개 열과 병합 셀 부재를 확인했다. 저장된 공식 원문의
전체 표 구조·괄호·품목 구분이 맞고 확인일이 유효할 때만 안내하며, 특정 요일을
물으면 해당 요일만 표시한다. 대형폐기물 수거·통계·시간 질문에는 이 표를 적용하지 않는다.

`SOURCE_ONLY_ANSWERS=false`인 경우에도 토큰 제한 종료, 미완성 문장·강조,
480자를 넘는 모델 응답을 그대로 표시하지 않고 범위를 좁히는 질문을 한다.
부분 답변의 끝을 삭제하면 예외를 잃을 수 있으므로 그런 방식으로 짧게 만들지 않는다.

- 확인: 2026-10-08 00:50, 로컬 FastAPI와 실제 Supabase, `SOURCE_ONLY_ANSWERS=true`.
- 실제 API 6개 사례: 전체 요일 분리수거, 수요일 분리수거, 혼합배출 주의사항,
  무료법률상담 방법, 성인 신규 여권 서류, 화재 신고. 핵심 안내 길이는 19~197자였다.
- 재현·검증 기록: `data/complete_answer_before.json`, `data/complete_answer_after.json`.
- 회귀 테스트에는 줄바꿈 문장, 미완성/긴 예외, 생략 경계, 괄호, 표 구조 변경,
  오래된 배출표, 모델 토큰 제한과 긴 응답을 포함한다. 실제 LLM 생성 전체 및 모든
  주민 질문의 정확도를 보장하는 평가는 아니다.
- 2026-10-08 00:52, 단위·회귀 테스트 113개 통과.

### 2026-10-08 보건소 운영시간 질문의 답변 항목 보정

`보건소 여는시간 알려줘`가 주소만 반환하는 현상을 실제 API에서 재현했다.
원문의 `진료시간 :`과 다음 줄을 연결할 때 `9:00`의 콜론을 새 항목명으로 오인하여
시간 항목이 선택에서 빠졌다. `사하구 보건소 운영시간 알려줘`는 별도 시설인
마을건강센터 자료를 선택하는 문제도 확인했다.

- 항목명·값의 줄바꿈을 연결하고 시간 표기의 콜론을 새 필드와 구별한다.
- 운영시간을 묻는 답변에는 실제 시간·휴무 항목이 있어야 한다. 시간·방법·조건 등
  질문 의도가 명확하면 단순한 시설명 일치로 주소를 대신 선택하지 않는다.
- 일반 보건소 시간 문의는 공식 보건소 안내 URL `health/contents.do?mId=0103000000`을
  사용한다. 마을건강센터·예방접종·검사·보건증 등 세부 업무는 각각의 근거를 검색한다.
- 시간 질문의 시설·업무를 검색 주제로 유지하되 `운영`이라는 표현이 원문에 반드시
  있어야 하는 제약은 제거한다. `몇 시까지` 같은 표현에도 변동 정보의 7일 기준을 적용한다.
- 점심시간과 검사·예방접종의 업무종료 30분 전 방문 안내는 짧은 답변에도 함께 유지한다.
- 회귀 테스트 127개 통과. 재현 기록: `data/opening_hours_before.json`.
- 실제 Supabase 및 `SOURCE_ONLY_ANSWERS=true`인 로컬 API에서 7개 질문을 확인했다.
  보건소 시간 표현 4가지, 보건소 위치, 마을건강센터 시간, 보건증 수수료를 점검했다.
  보건소 시간 답변은 108자로 점심시간과 30분 전 방문 안내를 포함했고, 다른 시설의
  시간을 가져오거나 주소로 대신 답하지 않았다. 기록: `data/opening_hours_after.json`.
  이 결과는 해당 표본과 회귀 테스트 결과이며 전체 상담의 정확도를 의미하지 않는다.

### 2026-10-08 접종 장소 질문의 답변 항목 보정

`백신 접종 하는곳 알려줘`가 장소 대신 과거 폐렴구균 접종 이력에 따른
`접종 불필요` 문장을 출력하는 문제를 실제 API에서 재현했다. 장소 의도를 구분하지 않고
일반 주제어가 많이 포함된 문장을 선택하던 것이 원인이었다.

- 종류 없는 접종 장소 문의는 백신 종류 한 가지만 먼저 묻는다. `독감`, `폐렴구균` 등
  짧은 답을 기존 장소 문의에 연결하며, 이름이 있는 새 비용·대상 질문은 새 의도로 처리한다.
- 실제 장소·주소 항목이나 명시적인 방문·접종 장소 문장을 요구한다. 의료기관이 등장하는
  과거 접종 이력·대상 조건을 장소로 사용하지 않는다. 콜론 없는 장소 표의 행 제목과 값도
  연결하되 다른 필드·무관한 셀을 임의로 결합하지 않는다.
- 공식 성인 예방접종 페이지의 백신별 구역을 구분한다. 장소를 먼저 안내하고 65세 이상
  사업 범위, 보건소 접종 미운영, 지자체 대상자의 지역 제한 및 연도별 지정기관 확인 안내를
  함께 유지한다. 어린이·다른 제품·임신부 등 별도 사업에 이 페이지의 안내를 대입하지 않는다.
- 장소·시간·비용의 후속 질문은 새로 묻는 항목을 우선한다. 장소 질문에는 최근 7일의
  웹 확인 기준을 적용하며 공식 행정 근거로 확인되지 않는 접종기관은 만들어내지 않는다.
- 일반 보건소 위치 질문은 특정 교육실이 포함된 사업 문서로 답하지 않고 공식 보건소
  찾아오시는 길로 연결한다. 여러 장소 값이 이어진 표를 단일 장소 행으로 오인하지 않는다.
- 2026-10-08, 단위·회귀 테스트 144개 통과. 재현 기록: `data/vaccine_location_before.json`.
  이 수치는 회귀 테스트 통과 수이며 전체 주민 질문에 대한 정답률이 아니다.
- 2026-10-08 12:13, 실제 Supabase와 로컬 FastAPI(`SOURCE_ONLY_ANSWERS=true`)에서
  8개 상담 턴을 점검했다. 원래 질문 → 독감/폐렴구균 선택 흐름, B형간염 장소,
  보건소 시간·위치, `독감 어디서 맞아?`를 확인했다. 핵심 답변은 42~193자였고
  필요한 장소·사업 범위·지역 제한을 포함했다. 출처의 확인일은 2026-10-07이다.

## 6. 향후 작업에 참고할 순서

1. 실제 주민 질문의 오답과 근거 연결 문제를 찾아 정확성과 최신성을 개선한다.
2. 100개 이상 평가 질문과 독립 검증셋을 보강하고 검색·답변·환각·연락처 지표를 측정한다.
3. 고우니의 상담 상태·행정정보 카드·모바일·접근성을 사용자 테스트로 개선한다.
4. 첨부문서 처리, 증분 갱신·삭제 동기화, 운영 장애 대응을 확인하고 필요한 부분을 보완한다.
5. 실제 기술 스택에 맞춰 실행 안내, API 명세, 구성도, 시연·장애 대응 문서,
   결과보고서와 발표자료를 현행화한다.

이 순서는 현재 사용자 요청과 계획서의 목적을 바탕으로 정리한 개발 참고 순서다.
계획서의 9~12월 일정은 당시 로드맵이며, 이후 요청과 진행 상황에 맞춰 조정한다.

팀 업무 분담은 총괄·데이터 품질·평가, UI/UX·고우니·사용자 테스트,
백엔드·DB·보안·운영, RAG·환각 억제·답변 품질의 네 영역으로 구성되어 있다.
