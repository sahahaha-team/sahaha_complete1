## 2. 프로젝트 목적

**프로젝트명: 사하구청 AI 상담사 프로토타입 고도화**

1학기에 구축한 공식 홈페이지 수집·정제, RAG 검색, 멀티턴 대화, 출처 제공,
개인정보 차단, 반응형 웹을 바탕으로 실제 행정 상담에 가까운 수준으로 고도화한다.
주민이 복잡한 홈페이지 메뉴를 찾아다니는 시간을 줄이고, 자연어 질문으로 필요한
공식 정보와 담당 부서·연락처·첨부서류를 확인하게 하는 것이 목적이다.

1학기 평가에서 제시된 핵심 보완 방향은 다음과 같다.

1. **환각 억제:** 검색 근거가 부족할 때 잘못된 행정정보를 생성하지 않도록 한다.
2. **사하구 특화 UI:** 고우니와 행정정보에 맞는 화면으로 서비스 정체성을 강화한다.
3. **객관적인 성능 검증:** 실제 행정 질문과 재현 가능한 평가 기준으로 정확도를 입증한다.

## 3. 개발에서 우선할 기준

### 정확한 근거와 최신 정보

- 공식 자료에 없는 날짜·금액·자격 조건·절차·부서·전화번호를 생성하지 않는다.
- 검색 결과가 질문의 실제 핵심 업무와 일치하는지 확인한 뒤 답한다.
- 근거가 부족하면 답변을 보류하거나 문의 내용을 구체화하는 질문을 한다.
- 공지사항 목록의 담당부서 열, 페이지 이동 메뉴, 저작권 안내를 행정 답변으로 사용하지 않는다.
- 대표전화와 업무 담당자의 직통번호를 구분하고 공식 데이터와 교차 확인한다.
- 보고서의 통계는 자료 기준 기간을 함께 표시한다. 과거 통계를 현재 행정서비스의
  금액·대상·운영 조건에 적용하지 않는다.
- 원문 출처와 실제 답변 내용이 일치하도록 한다.
- 신뢰도는 임의의 확률 대신 ‘공식 자료 확인됨’, ‘담당 부서 확인됨’,
  ‘정확한 자료를 찾지 못함’, ‘추가 문의 필요’ 등의 근거 상태로 표현한다.

### 검색과 연락처 안내

계획서의 검색 구조는 **메타데이터 필터 + 벡터 의미 검색 + BM25 + 직원업무안내**다.
분야별 문서 탐색, 가중치 통합과 재정렬, 필요할 때 검색 범위 확대를 수행하며
Recall@5와 MRR 등으로 설정을 비교한다.

현재 추가된 사용자 요구는 **담당 부서와 전화번호 질문을 전용 파일에서 빠르게
답변하는 것**이다. 이 질문에는 로컬 공식 업무·연락처 자료를 먼저 조회한다.
구체적인 업무·지역을 확인하고, 담당자가 겹치면 추가 질문을 한다.
단어가 비슷하다는 이유로 관련 없는 담당 부서를 연결하지 않는다.

첨부 PDF·HWP·HWPX 본문까지 검색 범위를 보강하는 것은 계획서의 개발 항목이다.
파일 형식별 실제 처리 가능 범위와 출처·기준 기간 보존을 확인하며 확장한다.

### 고우니와 행정 상담 UI

계획서가 제시한 상태 표현은 다음과 같다.

| 상태 | 표현 | 적용 상황 |
|---|---|---|
| 기본 | 인사하는 고우니 | 환영 화면과 일반 답변 |
| 검색 | 고민하는 고우니 | 공식 정보를 검색 중 |
| 주의 | 안내하는 고우니 | 개인정보 감지 또는 근거 부족 |
| 완료 | 밝게 안내하는 고우니 | 공식 자료·담당 부서 확인 완료 |

상담 결과에서 핵심 답변, 담당 부서, 공식 전화번호, 원문 링크, 첨부 신청서·안내문,
후속 질문, 정보 확인 상태를 쉽게 확인하도록 한다.
생활 분야별 빠른 질문, 모바일 사용성, 라이트·다크 모드, 키보드 탐색,
대체 텍스트 및 색상에만 의존하지 않는 상태 안내도 계획에 포함된다.

고우니의 반응과 정보 확인 상태가 상담 진행 과정에 맞게 연결되는 경험을 지향한다.

### 문맥과 개인정보

- 최근 문맥을 유지하되 새 주제에 이전 질문의 내용이 잘못 섞이지 않도록 한다.
- 모호한 질문은 대상·연령·분야·지역 등 필요한 범위를 확인한다.
- 역질문에서는 관련성이 낮은 출처를 보여주지 않는다.
- 새 대화 시작 시 문맥을 초기화한다.
- 개인정보가 포함된 입력을 차단하고 대화 이력에 저장하지 않는다.
- 화재 신고에서는 입력한 주소·연락처를 재사용하거나 저장하지 않고 공식 안전 안내만 제공한다.
- 답변에 개인정보가 섞이면 마스킹한다.

### 데이터 갱신과 운영

계획서에는 매일 증분 크롤링, ETag·Last-Modified 확인, 새 페이지와 변경 페이지 처리,
삭제 페이지·벡터 데이터 동기화, 검색 인덱스 갱신이 포함되어 있다.
스캔 PDF의 OCR은 적용 가능성을 검토하는 항목이다.

관리자 인증, 요청 횟수 제한, Supabase 접근 권한, 오류 정보 보호와
검색·생성 단계 장애 시 안전 안내를 유지한다.
대화 이력은 저장 정책에 맞게 관리하고, 영구 저장을 활성화한 경우 삭제 주기를 확인한다.

## 4. 평가 목표 — 계획서 기준

### 데이터셋

최소 **100개 이상**의 실제 행정 질의를 구성하고 튜닝용과 최종 검증용을 분리한다.
행정정보, 복지, 민원, 부서, 연락처, 모호한 질문, 도메인 외 질문,
개인정보 포함 질문, 첨부문서 질문을 포함한다.

### 지표

| 구분 | 확인할 지표·항목 |
|---|---|
| 검색 | Recall@1·3·5, MRR, 출처 적합률, 담당 부서 정확도, 첨부문서 검색 성공률 |
| 답변 | 정답 핵심어, 공식 원문과 의미·조건의 일치, 실제 사용한 출처의 적합성 |
| 환각 | 존재하지 않는 날짜·금액·절차·연락처, 근거 부족 질문에 대한 안전 안내 |
| 개인정보 | 입력 차단, 이력 저장 차단, 출력 마스킹 |
| 안정성 | 관리자 인증, 요청 제한, XSS 방어, DB 권한, 검색·모델 장애 대응 |

- **환각률** = 공식 자료로 확인할 수 없는 내용을 생성한 답변 수 ÷ 전체 평가 답변 수 × 100
- **환각 방어율** = 답변 불가능 질문에 안전하게 거절한 수 ÷ 답변 불가능 질문 수 × 100

학생 및 일반 사용자 **10명 이상**에게 이해도, 정보 탐색 편의, 출처·담당 부서 확인,
고우니 상태의 직관성, 모바일 사용성, 기존 홈페이지 대비 탐색 속도,
사하구 서비스 정체성을 평가받는다. 5점 척도와 자유 의견을 함께 수집한다.

이 수치들은 수행 목표다. 단위 테스트 통과나 소수 시연 질문의 성공을 전체 정답률이나
환각률로 바꾸어 발표하지 않는다. 평가 결과에는 데이터셋·채점 기준·실행 조건·시점을 기록한다.

### 2026-10-07 화재 신고 오답 수정

`당리동 인근 공장 화제 신고는 어떻게해?`에 불법주정차 단속 안내가 출력되는
현상을 재현했다. 지역명·신고 표현 또는 검색 점수만으로 관련 없는 자료를
근거로 인정하던 검사를 수정했다. 화재 신고는 공식 대피·119 안내를 우선하며,
행정 문서는 핵심 업무·원문·최종 발췌 구간을 확인한다. 여권 준비물 요청과
불법주정차 신고 구간도 함께 보정했다. 사하구청 화재 행동요령 페이지를 실제
DB에 추가했다. 이 수정의 검증 결과는 재현 사례 및 표본 질문에 대한 결과이며,
전체 상담의 정답률을 보장하는 수치로 사용하지 않는다.

- 실행: 2026-10-07 22:46, 로컬 FastAPI·실제 Supabase 자료·`SOURCE_ONLY_ANSWERS=true`.

## 6. 향후 작업에 참고할 순서

2026-10-09 사용자는 홈페이지의 모든 정보를 바탕으로 답변하려면 정보 수집이 가장
중요하다고 다시 강조했다. 전체 공개자료 탐색·본문/첨부 추출·검색 DB 반영·누락 점검을
우선하며, 개별 예상질문에만 맞춘 답변을 전체 서비스 완성으로 취급하지 않는다.
05:17 KST 점검에서는 페이지·첨부 2,307건이 fetched, 3,568건이 pending이었고,
검색 반영 대기는 31건이었다. 문화관광·보건소·도서관·문화회관 등 연결 사이트가
수집 범위에 포함되지만 아직 완료되지 않았다. robots 제한, 요청 실패, 본문 추출 실패는
따로 기록돼 있으며, 수집 건수를 전체 홈페이지 정보의 수집률로 표시하지 않는다.
전체 탐색·자동 갱신 Worker·수집 후 진단 프로세스는 실제 실행 중임을 확인했다.

1. 전체 공개 사이트·첨부자료의 수집과 검색 반영을 우선하고 누락·실패·변경·삭제 갱신을 점검한다.
2. 실제 주민 질문의 오답과 근거 연결 문제를 찾아 정확성과 최신성을 개선한다.
3. 100개 이상 평가 질문과 독립 검증셋을 보강하고 검색·답변·환각·연락처 지표를 측정한다.
4. 고우니의 상담 상태·행정정보 카드·모바일·접근성을 사용자 테스트로 개선한다.
5. 실제 기술 스택에 맞춰 실행 안내, API 명세, 구성도, 시연·장애 대응 문서,
   결과보고서와 발표자료를 현행화한다.

이 순서는 현재 사용자 요청과 계획서의 목적을 바탕으로 정리한 개발 참고 순서다.
계획서의 9~12월 일정은 당시 로드맵이며, 이후 요청과 진행 상황에 맞춰 조정한다.

팀 업무 분담은 총괄·데이터 품질·평가, UI/UX·고우니·사용자 테스트,
백엔드·DB·보안·운영, RAG·환각 억제·답변 품질의 네 영역으로 구성되어 있다.
