# RAG 단계별 개선·검증 — 2026-10-13

## 범위와 기준

사용자는 교수님 피드백에 따라 공통 근거 판정, 필요한 경우 검색 확장,
의미 재정렬 검토, 비교 평가를 순서대로 진행하고 검증된 단계마다 커밋하도록 요청했다.
기준 커밋은 `8e89b5b`이며 브랜치는 `hellokack/fix-chat-rendering`이다.
모델은 Ollama `gemma2:2b`를 유지한다.

검색 유사도·BM25·재정렬 점수는 답변의 정답 확률이 아니다. 공식 출처,
질문의 업무·요청 항목·조건을 검증하고 결과를 답변·부분 안내·확인 질문·보류로 나눈다.

## 비교 조건

- 기준 코드의 별도 복사본과 현재 코드를 각각 실행한다.
- 실제 Supabase `raw_pages` 182개와 `documents` 794개를 읽기 전용으로 저장한 동일 자료를 사용한다.
- 벡터 검색은 저장된 384차원 임베딩에 대한 로컬 정확 코사인 검색으로 재현한다.
  Supabase HNSW 검색·HTTP·DB 지연을 측정한 결과로 해석하지 않는다.
- 실제 로컬 임베딩 모델과 Gemma를 사용한다. 시나리오별 새 세션을 사용하고 대화 영구 저장은 비활성이다.
- 반복 개발 질문 29시나리오 34턴과 신규 진단 질문 30개, 총 59시나리오 64턴이다.
  신규 질문 중 진단에 사용한 문항은 독립 최종 검증 표본으로 표시하지 않는다.
- 원문 내용·코드 해시·자료 해시·질문·응답·조건·시각을 로컬 `data/rag_upgrade_20261013/`에 보존한다.
  API 키·비밀번호·사용자의 실제 대화는 저장하지 않는다.
- 비교 실행 일부는 다른 모델 검사와 동시에 실행했다. 해당 소요시간은 서비스 지연의 절대 성능 보장이 아니다.

## 1단계 — 공통 근거 판정

- `evidence_decision.py`에서 공식 출처·업무·시점·본문 근거와 요청 필드의 포함 여부를 분리한다.
- 관련 자료가 있어도 장소·비용 등이 없으면 `partial` 또는 `needs_evidence`로 기록한다.
  검색 점수가 높다는 이유로 다른 업무를 통과시키지 않는다.
- 판정의 단어 일치 단계는 아직 유지한다. 의미 관련성 보강은 이후 단계에서 검토한다.
- 조회 장애와 최신성 미확인, 충분한 근거 미확인을 구분해 안내한다. 서비스가 존재하지 않는다고 단정하지 않는다.
- API 근거 메타데이터에 판정·사유·요청 필드·확인 필드를 제공한다. 주민 UI에는 구현 점수를 표시하지 않는다.
- `CONFIDENCE_MIN_SIMILARITY`의 설명을 실제 후보 신호 역할에 맞게 수정한다.
- **364개 단위·회귀 검사 통과**, 실제 모델과 고정 자료로 7시나리오 9턴 점검.
  여권 야간 창구·미성년자 서류, 소파 규격 후속, 수급자 등본 면제 후속은 유지했다.
  보건소 일반 시간 문의에 임신 초기검사를 선택하는 문제 등은 남았으며 해결된 것으로 계산하지 않는다.
- 이 수치들은 상담 정답률이 아니다. 공통 판정 적용의 회귀 확인 범위다.

## 2단계 — 검증된 원문 빠른 조회와 검색 확장

- 원문·BM25 결과가 있다는 이유로 의미 검색을 종료하지 않는다. 공식 원문에서 요청
  필드를 확인했고 업무 제목이 일치하는 단일 근거만 빠른 조회로 종료한다.
- 나머지는 BM25·벡터·원문 후보를 URL별 RRF 순위로 통합한다. 같은 URL의 많은 청크가
  여러 표를 얻어 다른 출처를 밀어내지 않도록 검색기별 URL당 한 번만 반영한다.
- 원본 코사인 유사도, BM25 점수, RRF 점수를 분리한다. 후보 수집 최소값은 기본0.35이며
  이 값 자체로 답변을 허용하지 않는다. 파서·근거 판정과 후속 의미 검사가 별도로 필요하다.
- 벡터 조회 장애를 빈 검색 결과로 숨기지 않고 키워드 후보와 장애 사유를 함께 반환한다.
- 임베딩 CPU 스레드를 기본2개로 제한하고 질문 벡터를 메모리에 최대256개·10분 캐시한다.
  벡터 캐시는 자료의 사실을 저장하지 않으며 원문 갱신·출처 검증을 계속 수행한다.
- 일반 보건소 시간 문의에는 개별 임신·접종·센터 사업 시간을 사용하지 않는다.
  다른 구의 보건소 요청도 사하구 안내로 대체하지 않는다.
- **372개 단위·회귀 검사 통과**, 고정 공식 자료와 실제 모델로14시나리오16턴 확인.
  여권·소파·수수료 면제 후속을 유지했고 보건소 시간·주소와 다른 구 문의를 보완했다.
  금연 표현에 세금 자료를 선택하거나 실시간 주차 잔여면수에 일반 표를 선택하는 문제는
  남아 있다. 이후 의미·요청 항목 검증 단계의 진단 사례로 사용한다.
- 기준64턴,1단계9턴,2단계16턴의 파일은 각각 `baseline.json`, `stage1.json`, `stage2.json`이다.

## 3단계 — 필요한 후보의 의미 재정렬

- 공개 소형 모델 `cross-encoder/mmarco-mMiniLMv2-L12-H384-v1`을 설치하고,
  최근 공식 원문을 확인한 불명확한 후보에만 적용한다. Gemma는 변경하지 않는다.
- CPU의 자원 사용을 고려해 상위8개 출처, 출처당 최대2개 현재 원문 구간을 검사한다.
  점수는 원본 logit이고 상위 점수·1위와2위의 차이를 후보 관련성 신호로 사용한다.
  기본 기준−2.0·차이1.5는 개발 진단용 값이며 정답 확률로 보정한 값이 아니다.
- 의미 관련성이 확인된 출처는 현재 원문에서 확인한 업무 표현으로 원문 필드를 읽는다.
  질문·URL·제목·본문 해시에 판정을 결합하며 변경된 원문·다른 질문에는 사용하지 않는다.
  명시한 다른 구·사업, 과거 자료, 없는 장소·수수료·조건을 허용하는 규칙은 아니다.
- 분류 태그는 전체 벡터 후보를 차단하지 않는다. 원문의 `예)`·`ex)`와 필드 소제목을
  처리하고, 요청한 특정 범위를 확인하지 못하면 부분 안내에 그 한계를 명시한다.
- 실시간 잔여 주차면수와 의약품·복용 정보는 일반 주차 표·클리닉 소개로 대체하지 않는다.
- 로컬 모델이 없거나 실패하면 기존 근거 검사로 이어진다. 웹에서 자동 다운로드하지 않는다.
  준비 명령은 `python scripts/setup_reranker.py --download`이며 추가 DB 설정은 없다.
- **387개 단위·회귀 검사 통과**. 실제 모델 진단에서 금연 문의의 세금 목록 오선택,
  음식물 제외품목의 원문 누락, 요일 예약기간 문장의 누락을 보완했다.
  세무 장부 대행처럼 현재 원문에 명시되지 않은 세부 사항은 확답하지 않는다.

### 평가 재현기 교정

초기 `baseline.json`, `stage1.json`, `stage2.json`과 초기3단계 진단은 재현기가
`select("id, content, metadata")`의 공백을 처리하지 못해 BM25 본문을 누락했다.
원문·벡터·Gemma 경로는 실행됐지만 완전한 하이브리드 검색 비교가 아니므로,
이 파일로 단계별 답변 개선율을 계산하지 않는다. 재현기를 교정하고794개 BM25 행의
실제 로딩을 필수 확인한 `baseline_corrected.json`과 최종 실행을 비교한다.
단위·회귀 검사의 결과는 이 오류와 별개이며 실제 웹·DB 경로도 별도로 검증한다.

## 최종 비교와 적용

### 전체 비교에서 확인한 추가 경계

- `baseline_corrected.json`과 `final_safe.json`은 각각 동일한64턴을 실행했고 코드 변경
  검사도 통과했다. 마지막 경계 보강 전 비교이며 현재 버전 전체 정답률로 표시하지 않는다.
- 의미 재정렬이 특정 질문의 업무를 바꾸는 사례를 확인해 알려진 업무 이름을 유지한다.
  특정 시설·사업은 담당 제목·프로그램 제목·소유 행에서 확인하고 단순 언급으로 허용하지 않는다.
- 의료 프로그램의 서류를 일반 행정정보 공동이용 답변으로 사용하지 않도록 범위를 확인한다.
- 표준 예약 필요·비용 표현을 인식하고 복합 답변의 누락을 명시한다. PDF에서 앞 문장이
  없는 연결절은 독립 사실로 쓰지 않는다. 내용이 없는 원문은 추정으로 완성하지 않는다.
- Ollama의 `timeout` 이름은 설치된 `ChatOllama`에서 지원하지 않아 무시되고 있었다.
  `client_kwargs`에 실제 시간 제한을 전달하고 선택 요청은 `stream=False`로 받는다.
  전체 검색·전처리 시간을 포함한 서비스 지연 상한을 보장하는 변경은 아니다.
