- 인감 서류 문의에서 일반적인 `동 주민센터`를 특정 시설 소유 제목으로 요구한 오류와, 질문의 `대리`를 원문의 `위임`과 연결하지 못한 사전 필터를 수정했다. 특정 시설의 주소·시간 확인은 계속 엄격하게 검사한다. 모델 근거 준비와 원문 fallback 모두 같은 세부 항목 검사를 사용한다.
- 공식 [정보공개청구 및 처리절차](https://www.saha.go.kr/portal/contents.do?mId=0302010300)를 10/16 실제 수집하고 HTML·확인시각·본문·6개 청크와 벡터를 저장했다(1/1 페이지, 적재오류0). 우선 갱신 대상에도 추가했다. 과거 통계 보고서로 현재 기한을 추정하지 않는다.
- `청구인` 단계의 이름만 좁혀 읽어 같은 상위 처리절차의 결정기간을 놓치는 현상을 보완했다. 요청 업무가 제목에 있는 상위 구간만 검토하며 다른 증명서의 수수료를 차용하지 않는 반례를 유지했다.
- 전체 회귀 **458개 통과**, 10/16 12:46 KST. 첫 샌드박스 실행은 임시폴더 권한 오류로 중단했으며 통과 결과로 사용하지 않았다. 전용 임시폴더에서 전체 재검사했다.
- 마지막 실제 API **3턴**, `stage_f_ready.json`, 코드 해시 불변. 인감 대리 서류는 위임받은자 신분증·서명/날인된 위임장·위임자 신분증을14.254초에 안내했다. 본인서명사실확인서는 본인 신분증으로 구분(6.567초). 정보공개 결정은 청구받은날10일 및10일 범위 연장·사유 문서 통지를 함께 안내(1.025초).
- 최초 `stage_f.json`은 인감이 여전히 거절된 개발 진단이므로 최종 통과로 계산하지 않는다. 해당 실패를 바탕으로 두 번째 필터를 고쳤다. 인감 출처의 실제 확인일은10/11이며 새 수집 페이지는10/16이다. 모든 출처를 오늘 재확인했다고 표현하지 않는다.
- 최종 미관찰 검증 질문22개는 `evaluation/accuracy_untouched_20261016.json`에 고정했다. 기존10가족의 새 표현10개, 추가 행정질문10개, 허구전제/긴급2개다. F 재현 질문에만 수정 단서를 사용했고 이22개의 답은 아직 관찰하지 않았다.

## G. 과도한 세부 항목 검사로 생긴 표현 회귀 수정

- F 뒤 전체 검사 중 `닭뼈와 조개껍데기`가 원문의 `동물의 뼈·조개류의 껍질`을 놓치는 회귀를 발견했다. 실제 남은 미해결어는 `껍데기`였다. 공통 용어 해석에 `껍데기→껍질` 동의어만 추가했고 음식물 처리 정답이나 새 분류 규칙을 넣지 않았다.
- F 최종 시도는 기본54턴 완료·확장22턴 진행 후 중단했다(`pre_g_core.json`, `pre_g_extended_partial.json`). 그 안의 N020 실패를 성공으로 바꾸어 집계하지 않는다. 미관찰22개는 아직 실행하지 않았다. 최종 평가는 G 코드로 다시 수행한다.
- 전체 회귀 **459개 통과**. 원문에 없는 국물 문의를 같은 제외 예시로 대체하지 않는 반례도 유지했다.
- 실제 API **2턴**, `stage_g_ready.json`, 코드 해시 불변: 제외 품목 질문은16.217초에 실제 목록을 안내하고 라면 국물은9.407초에 세부 근거 미확인을 표시했다.
- 최초 재시작은 모델/원문 초기화가 길어 준비 제한시간에 도달했다(`accuracy_stage_g_api.log`). 응답 평가를 시작하지 않았으므로 정답률/응답시간에서 제외했다. 새 시도는 준비 완료 후 실행했다. 초기화 지연 원인은 확정하지 않았으며 준비 완료가 항상3분이라는 보장도 하지 않는다.

## H. 확대 검증에서 발견한 요청 해석과 오래된 세부 안내 보완

- G의 140턴(54+28+36+22)을 실행했다. 기존 미관찰 V22에서도 신규 신분증 순서 거절, 미성년 여권의 챙길 것 오해, 검사 후 인터넷 발급 대신 검사 절차 안내, 복용량 대신 서비스 안내, 소송 중 신청 가능 여부 오해, 가스가 새는 사건 누락을 발견했다. V22는 이제 개발셋이며 독립 검증으로 재사용하지 않는다. 질문 문구는 보존했다.
- 공통 요청 항목 해석, 청소년/성인 확인과 후속 연결, 검사 완료 후 온라인 발급의 소유 항목, 자료에 없는 약품·복용량의 명시적 보류를 보완했다. 가스 사건 활용형을 추가하되 예방교육은 긴급 사건으로 취급하지 않는다.
- 사하구 온라인 발급 원문의 오래된 공인인증서/고객센터 줄만 격리한다. 현재 [공공보건포털 이용안내](https://www.e-health.go.kr/gh/caSrvcGud/selectUsrGudInfo.do?menuId=200016)의 인증 방식과 다르기 때문이다. 정상 검사 결과만 온라인 발급 가능, 검사일부터 1년 발급 범위 등 실제 유효한 조건은 유지한다. 모델 기억으로 새 전화번호를 채우지 않는다.
- 조회 장애를 자료 만료라고 잘못 표시한 경로를 수정했다. 검증 조회 실패는 retrieval_error이며, 확인일이나 유효기간을 바꾸지 않는다. 감사 실행기는 공식 자료 검토 설정과 연락처 파일 해시도 기록한다.
- 전체 회귀 **466개 통과**, 10/16 13:52 KST, 12.393초. 실제 상담 API **10턴**, 15:35~15:37 KST, `stage_h_ready.json`, 실행 내부 코드·자료 설정 해시 불변, Gemma2:2b. 신규 순서·부모 방문 재발급·청소년 예약 후속·온라인 발급 조건·소송 제외·가스 즉시 안전 안내·자료연도 주의를 원문과 대조했다. 복용량과 예방교육은 미확인으로 남는다. 최대24.436초이며 속도 문제가 모두 해결된 것은 아니다.
- 최초 H 실행은 서버 준비 제한시간에 도달해 평가를 시작하지 못했다. 그 실패를 응답 통계에 포함하지 않는다. 다음 독립 문항 U22는 `evaluation/accuracy_validation_20261016.json`에 고정했으며 아직 응답을 관찰하지 않았다.

## I. 사용자 운영 환경에 맞춘 Gemma4와 vLLM 지원

- 사용자 확인 운영 구성은 내부망 vLLM0.25.1/Gemma4-26B다. 학교 접속 주소는 없어 실제26B를 시험하지 못했다. Google 공식 공개 라이선스/지원 문서를 확인하고 이16GB PC는 Ollama0.40.0/Gemma4:E4B로 전환했다.
- 공급자 선택을 분리하고 vLLM의 모델ID·인증·JSON Schema·토큰제한·타임아웃과 오류 경로를 연결했다. vLLM 모드에서 Ollama를 호출하지 않는다. 모델의 자유 생성 문장을 행정 사실로 쓰거나 실패 때 다른 외부 서비스로 보내지 않는다. 기존 시스템 화면의 공급자 표시만 바로잡았다.
- 전체476개 회귀, 로컬 실제 근거 선택2건, 실제 상담 API10턴 검증. 단독 초기 빈 선택과 로딩87.512초는 별도 실패/초기화 기록으로 보존했다. 상세 조건은 `gemma4_runtime_20261016.md`에 기록한다. 추가 최종 독립 검증은 이어서 진행한다.

## J. 실제 분류표의 품목과 별도 배출 규칙 연결

- G에서 거절했던 헌 형광등 질문은 `넣으면 되나요`를 일반 서비스 종류로 오해했고, 표 안의 분류 소속과 별도 문장의 규칙을 연결하지 못했다. 조건 문의 활용형을 공통 해석에 추가했다.
- 분류 괄호 안의 실제 품목과 그 분류에 명시된 규칙을 같은 구간에서만 연결한다. 중첩 괄호·인접 분류·여러 품목의 업무명을 함께 검사한다. 파손/고장 등의 추가 조건에는 이 일반 분류 규칙으로 답을 확정하지 않는다. 특정 질문의 정답 문장은 코드에 넣지 않았다.
- 전체 회귀 **481개 통과**, 10/16 18:13 KST, 9.530초. 중간 반례 실패는 수정 후 전체 재검사했으며 초기 서버 준비 중 실행은 최종 평가에 합산하지 않는다.
- 실제 API **3턴**, 18:15~18:17 KST, `stage_j_confirmed.json`, 코드 해시 불변, Gemma4:E4B. 헌 형광등12.465초·폐건전지8.599초는 공식 재활용 분류와 종량제봉투 혼합 금지·품목별 분리 규칙을 함께 안내했다. 깨진 형광등은43.881초에 세부 근거 미확인으로 보류했다. 이 긴 지연은 해결되지 않은 성능 한계이며, 안전한 보류를 충분 답변으로 세지 않는다.

## K. 수집 태깅에서도 선택한 모델 공급자 사용

- 새 모델 평가 중 수집 후 태깅에 직접 Ollama 지정이 남아 있는 것을 발견했다. 상담과 같은 공급자 팩토리를 사용하며 단건/배치 JSON 스키마를 전달한다. 모델 태그로 원문의 URL·제목·분류·청크 번호를 변경하지 못하게 한다. 실패 시 원문 기반 메타데이터를 보존한다.
- 전체 **485개 회귀 통과**, 10/16 18:35 KST 무렵, 11.660초. 실제 로컬 태깅1건(합성 입력, DB 적재 없음)과 상담 API2턴에서 출처·신분증/전입과 무관한 의료 정보 혼동 없이 정상 응답을 확인했다. API2턴은 보건소 시간/주소 및 전입신고14일 질문이다. 원자료는 `metadata_provider_probe.json`, `stage_k_api.json`이다.
- 학교 vLLM 실제 접속은 여전히 미실시이며 단건/배치 요청·출처 보존·오류 처리는 회귀 검사로 구분한다. 평가 실행기의 해시에 processor/main/worker도 포함한다.
- J 코드로 실행한 Gemma4 확대 평가에서 F018의49.760초 중 모델36.450초(입력34.799초)를 확인해 최종 검사를 중단했다. `pre_l_core/extended/expanded.json`에 완료/부분 결과를 보존하며 이후 최종 결과와 합산하지 않는다. U 응답은 아직 검수하지 않았고 개선 단서는 개발 F018에서만 얻었다.
